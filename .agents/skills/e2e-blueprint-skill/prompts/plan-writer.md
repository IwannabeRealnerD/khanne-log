## 작성 절차

1. Playwright MCP 도구로 대상 앱(dev 서버 URL: {대상 앱 URL})의 실제 화면을 탐색하여 다음을 파악한다:
   - 페이지 구조: 어떤 페이지들이 있는지, 각 페이지의 주요 UI 요소
   - 페이지 간 이동 흐름: 네비게이션, 리다이렉트, 링크 등
   - 사용자 행동: 폼 입력, 버튼 클릭, 드롭다운 선택 등
   - 인증 흐름: 로그인/로그아웃, 인증 상태에 따른 리다이렉트
2. 코드베이스에서 다음을 확인한다:
   - 라우트 구조: `app/` 디렉토리의 페이지 라우트 (`page.tsx`, `layout.tsx`)
   - 미들웨어: 인증 체크, 리다이렉트 로직 (`middleware.ts`)
   - 기존 E2E 테스트: `e2e/tests/<앱명>/` 하위에 이미 작성된 테스트가 있는지 확인하여 중복 방지
   - `e2e/constant.ts`의 `GLOBAL_APP_URLS`에서 대상 앱의 URL 확인 (등록되지 않은 앱이면 URL 추가)
3. 프로젝트의 `.claude/skills/` 디렉토리를 재귀 탐색하여 모든 `SKILL.md` 파일을 찾는다
4. 각 스킬의 `name`과 `description` (YAML frontmatter)을 읽어 스킬 목록을 구성한다
5. 작업 내용과 각 스킬의 description을 대조하여 관련 스킬을 선별한다 (E2E 테스트의 경우 `e2e-skill`이 항상 포함)
6. 선별된 스킬의 본문을 읽어 파일 구조·위치·네이밍 규칙을 파악한다
7. 선별된 스킬을 기준으로 Step을 나눈다 (스킬 1~2개 = Step 1개)
8. 각 Step의 `참조 스킬` 필드에 해당 스킬 명시
9. 계획 템플릿({프로젝트 루트}/.claude/skills/e2e-blueprint-skill/templates/blueprint-templates.md)을 읽고 형식에 맞게 계획 파일을 작성한다
10. 파일 상단에 `## 요약` 섹션을 작성한다. 사람이 한눈에 파악할 수 있도록 "뭘 하는 건지 / 어떻게 하는 건지 / 테스트 범위"를 간결하게 정리한다

## 🛑 MCP 탐색 중 중단 조건

MCP 탐색 단계(절차 1)에서 다음 상황이 발생하면 **계획 작성을 중단**하고 메인 에이전트에게 보고한다:

| 상황                                                | 대응                                        |
| --------------------------------------------------- | ------------------------------------------- |
| dev 서버 접속 불가 (페이지 로드 실패, 타임아웃)     | 서버 상태 보고 후 중단                      |
| 대상 페이지가 존재하지 않음 (404, 빈 화면)          | 스냅샷 결과와 함께 중단                     |
| 사용자 요청의 기능/페이지가 앱에 구현되어 있지 않음 | 실제 앱 상태 vs 요청 내용 차이 보고 후 중단 |
| 인증 벽에 막혀 대상 페이지 탐색 불가                | 인증 요구사항 보고 후 중단                  |
| MCP 도구 반복 에러 (3회 이상)                       | 에러 내용 보고 후 중단                      |

**중단 보고 형식:**

```
🛑 [계획 작성] 중단

**상황**: (MCP 탐색 중 무엇을 확인하고 있었는지)
**이상 내용**: (무엇이 예상과 다른지)
**시도한 것**: (해결을 위해 시도한 내용, 있다면)
**판단**: (왜 계획 작성을 계속할 수 없는지)
**필요한 조치**: (사용자가 확인/해결해야 할 것)
```

## Step 설계 규칙

- **자기완결적 계획**: 새 세션에서도 실행 가능해야 함. 유실되는 정보는 인라인 기록, 자동 로드되는 정보는 이름만 명시
- 항상 `.claude/skills/` 디렉토리를 탐색하여 최신 스킬 목록 사용 (매핑 테이블 의존 금지)
- 스킬 미매핑 작업은 `참조 스킬: 없음 (CLAUDE.md 컨벤션 적용)` 명시
- 맥락·템플릿 규칙은 `./templates/blueprint-templates.md`의 "기록 vs 참조 원칙" 따름
