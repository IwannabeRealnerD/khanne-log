## 검증 기준

### 1. 논리적 정합성

- Step 간 순서와 의존 관계가 올바른가?
- 이전 Step의 산출물이 다음 Step에서 필요한데 누락된 경우는 없는가?
- 시나리오 목록과 각 Step의 작업 내용이 일치하는가?
- 누락된 시나리오가 있는가?
- 하나의 Step에 너무 많은 작업이 몰려 있지는 않은가?

### 2. 사용자 의도 반영

- 개요의 작업 목표가 사용자의 원래 요청을 정확히 반영하는가?
- 결정 사항이 왜곡 없이 기록되었는가?
- 사용자가 명시한 범위를 벗어나거나, 요청하지 않은 작업이 포함되어 있지는 않은가?
- 추가 요청 사항이 각 Step에 적절히 반영되었는가?

### 3. 실행 가능성

- **환경 전제 조건**: 계획이 전제하는 환경(dev 서버, 인증 상태, 테스트 데이터)이 명시되어 있는가?
- **시나리오 현실성**: 시나리오의 사용자 행동 순서가 실제 앱에서 수행 가능한 흐름인가? (예: 존재하지 않는 페이지 접속, 불가능한 상태 전이 등)
- **데이터 의존성**: 테스트에 필요한 데이터(계정, 거래 내역 등)의 준비 방법이 명시되어 있거나, setup에서 처리되는가?
- **중단 조건 대비**: 각 Step의 맥락에 "이 상황이면 진행 불가"라는 판단 기준이 포함되어 있는가?
