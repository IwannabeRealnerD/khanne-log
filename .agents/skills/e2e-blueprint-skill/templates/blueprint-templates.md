# 계획 파일 템플릿

## 시나리오 작성 원칙

- **사용자 관점**: 구현 세부사항이 아닌, 사용자가 경험하는 흐름을 기술
- **URL과 행동만 기록**: locator(선택자)는 기록하지 않음 (e2e-writer가 실행 시 MCP로 직접 파악)
- **atomic 단위**: 하나의 시나리오는 하나의 독립적인 사용자 흐름을 검증
- **우선순위 표기**: 핵심 흐름(로그인, 주요 기능)을 먼저 배치

## 계획 파일 구조

````markdown
# [앱명] E2E 테스트 계획

## 요약

> 이 섹션은 사람이 계획 전체를 빠르게 파악하기 위한 것이다.
> 에이전트용 상세 내용은 아래 섹션들에 있다.

**뭘 하는 건지**: (한 문장으로 테스트 목표)

**어떻게 하는 건지**:

1. (Step 1 한 줄 설명)
2. (Step 2 한 줄 설명)

**테스트 범위**: (대상 기능/페이지를 간결하게 기술)

## 개요

- 대상 앱: `<앱명>`
- 대상 URL: `GLOBAL_APP_URLS.<앱키>` (e2e/constant.ts)
- 테스트 파일 위치: `e2e/tests/<앱명>/`
- 작업 목표 요약

## 배경/컨텍스트

- 왜 이 E2E 테스트가 필요한지

## 시나리오 목록

> 영향 범위(파일 tree) 대신, E2E 테스트는 시나리오 목록으로 범위를 표현한다.

### 시나리오 1: <시나리오 제목>

- **대상 URL**: `GLOBAL_APP_URLS.<앱키>` + 경로
- **사전 조건**: 인증 상태, 필요한 데이터 등
- **사용자 행동 순서**:
  1. <페이지>에 접속한다
  2. <요소>를 클릭/입력한다
  3. ...
- **기대 결과**: URL 변경, 화면 표시, 에러 메시지 등

### 시나리오 2: <시나리오 제목>

- ...

(필요한 만큼 시나리오 추가)

## 결정 사항

- (Step 2의 `## 질문` 섹션에서 사용자 답변이 완료되면, 질문/답변을 이 섹션으로 변환하여 맥락을 보존한다)
- (형식: `키워드: 확정된 내용` — 예: "테스트 대상: Dashboard 로그인 흐름")

## 구현 단계

> **실행 방식**: 각 Step은 `e2e-writer` 에이전트에 위임하여 실행한다.
> `e2e-writer`는 이 파일의 **개요·결정 사항·고려사항·추가 요청 사항**을 먼저 파악한 뒤,
> 해당 Step의 `참조 스킬` 파일(`.claude/skills/{스킬명}/SKILL.md`)을 읽고 규칙을 로드하여 작업을 수행한다.
> Step 완료 시 체크박스를 `[x]`로 업데이트한다.

### Step 1: [테스트 파일 단위 제목]

**참조 스킬**: `e2e-skill`
**목표**: 이 단계에서 작성할 테스트 범위
**대상 시나리오**: 시나리오 1, 시나리오 2
**테스트 파일**: `e2e/tests/<앱명>/<테스트파일명>.spec.ts`
**맥락**:

- (이 Step 실행에 필요한 배경 정보. 아래 "기록 vs 참조 원칙" 참고)

**작업 내용**:

- [ ] 세부 작업 1
- [ ] 세부 작업 2

---

(이하 동일 구조로 Step 추가)

## 고려사항

- 주의할 점, 엣지 케이스
- 실행 중 중단이 예상되는 조건 (예: "테스트 데이터가 없으면 Step 2 진행 불가", "인증 토큰 만료 시 재로그인 필요")

## 추가 요청 사항

- (사용자가 구현 시 반영해야 할 추가 요청을 자유롭게 기록)
- 예: "기존 login.spec.ts의 패턴을 따라서 구현해줘"
- 예: "인증이 필요한 테스트는 storageState를 사용해줘"

## 실행 방식

> Step이 2개 이상이면 이 섹션을 작성한다. Step이 1개면 생략 가능.

각 Step은 `e2e-writer` 에이전트에 위임하여 순차 실행한다.

**위임 프롬프트:**

```
다음 계획 파일을 읽고 Step N을 실행하세요.

계획 파일: {계획 파일 절대 경로}
프로젝트 루트: {프로젝트 루트 절대 경로}

실행 절차:
1. 계획 파일을 읽고 ## 개요, ## 결정 사항, ## 고려사항, ## 추가 요청 사항을 파악
2. Step N의 목표·맥락·작업 내용을 파악
3. 이전 Step에서 생성/수정된 파일이 있으면 해당 파일을 Read하여 현재 상태를 파악
4. Step의 `참조 스킬` 파일을 읽어 규칙 로드 ({프로젝트 루트}/.claude/skills/{스킬명}/SKILL.md)
5. Playwright MCP 도구로 대상 앱의 실제 화면을 탐색하며 시나리오의 UI 요소·흐름을 파악
6. 스킬 규칙에 따라 작업 내용을 순서대로 수행. 각 세부 작업 완료 시마다 체크박스를 [x]로 업데이트
7. 모든 작업 완료 후 ## 진행 상황 섹션의 해당 Step 체크박스를 [x]로 업데이트
```

**주의사항:**

- `e2e-writer` 에이전트로 위임 (Agent 도구, `subagent_type: "e2e-writer"`)
- Step 간 의존성이 있으므로 반드시 순차 실행 (병렬 실행 금지)

## 진행 상황

> 각 Step별 체크박스를 기록한다. 재개 시 이 섹션을 파싱하여 진행 지점을 결정한다.

- [ ] Step 1: [테스트 파일 단위 제목]
- [ ] Step 2: [테스트 파일 단위 제목]
````

## 기록 vs 참조 원칙

계획 파일은 **새 세션(컨텍스트 없음)에서도 실행 가능**해야 한다. 단, 자동 로드되는 정보까지 복사하면 컨텍스트 낭비다.

### 인라인 기록 (세션 간 유실되는 정보)

| 항목             | 기록 위치          | 예시                                        |
| ---------------- | ------------------ | ------------------------------------------- |
| 결정 사항        | `## 결정 사항`     | "로그인 테스트 계정: test@moin.com"         |
| 대상 앱·URL      | `## 개요`          | `GLOBAL_APP_URLS.DASHBOARD`                 |
| 시나리오 상세    | `## 시나리오 목록` | 사용자 행동 순서, 기대 결과                 |
| 기존 테스트 현황 | Step `맥락`        | "로그인 테스트는 이미 존재 (login.spec.ts)" |
| 인증 흐름        | Step `맥락`        | "미인증 시 /login으로 리다이렉트"           |

### 참조만 (새 세션에서 자동 로드)

| 항목            | 이유                          | 계획 파일에 적을 것                  |
| --------------- | ----------------------------- | ------------------------------------ |
| 스킬 규칙       | Step 진입 시 스킬 호출로 로드 | 스킬 이름만 (`참조 스킬: e2e-skill`) |
| CLAUDE.md 내용  | 세션 시작 시 자동 로드        | 적지 않음                            |
| UI 요소 locator | e2e-writer가 MCP로 직접 파악  | 적지 않음                            |
| 코드 구현 상세  | 파일에 이미 존재              | 파일 경로만                          |

### `맥락` 필드 작성 가이드

- **"새 세션에서 이 Step을 시작할 때, 탐색 없이 바로 작업할 수 있는가?"** 를 기준으로 판단
- 2~4줄로 간결하게 작성. 장황하면 컨텍스트 낭비
- 기존 테스트 현황은 파일 경로만 적고 코드는 복사하지 않음 (새 세션에서 Read로 확인)
- 인증 흐름은 리다이렉트 URL만 기록 (미들웨어 코드 복사 금지)

## 작업 유형별 Step 가이드

> 아래는 참고용 Step 구성 예시다. 실제 `참조 스킬`은 프로젝트의 `.claude/skills/`를 탐색하여 결정한다.

### 단일 페이지 테스트

| Step | 제목             | 주요 작업                                      | 맥락에 적을 것             |
| ---- | ---------------- | ---------------------------------------------- | -------------------------- |
| 1    | 인증 흐름 테스트 | 로그인/로그아웃, 인증 리다이렉트 테스트 작성   | 인증 URL, 리다이렉트 경로  |
| 2    | 핵심 기능 테스트 | 해당 페이지의 주요 사용자 시나리오 테스트 작성 | 대상 URL, 기존 테스트 현황 |

### 멀티 페이지 흐름 테스트

| Step | 제목             | 주요 작업                                         | 맥락에 적을 것                |
| ---- | ---------------- | ------------------------------------------------- | ----------------------------- |
| 1    | 진입 흐름 테스트 | 시작 페이지 접속, 네비게이션 확인                 | 시작 URL, 인증 필요 여부      |
| 2    | 핵심 흐름 테스트 | 페이지 간 이동을 포함한 주요 시나리오 테스트 작성 | 페이지 간 이동 순서, 기대 URL |
| 3    | 에러 흐름 테스트 | 에러 케이스, 엣지 케이스 테스트 작성              | 에러 조건, 기대 에러 메시지   |
