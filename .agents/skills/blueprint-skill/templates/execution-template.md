# execution.md 템플릿

> 에이전트가 실행 시 참조하는 문서. 계획의 본체(개요, 영향 범위, 결정 사항 등)는 `plan.md`에 있으며 중복 기재하지 않는다.

````markdown
# 실행 명세

> 계획: ./plan.md

## Step 메타데이터

> 각 Step의 제목과 목표는 plan.md와 동일하다. 여기에는 에이전트 실행에 필요한 참조 스킬과 맥락만 추가한다.

### Step 1: [단계 제목]

**참조 스킬**: `관련-skill-name`
**맥락**:

- (이 Step 실행에 필요한 배경 정보)

### Step 2: [단계 제목]

**참조 스킬**: `관련-skill-name`, `추가-skill`
**맥락**:

- (이 Step 실행에 필요한 배경 정보)

---

(plan.md의 Step 수만큼 반복)

## 실행 방식

> Step이 2개 이상이면 이 섹션을 작성한다. Step이 1개면 생략 가능.

각 Step은 독립된 서브에이전트에 위임하여 순차 실행한다.

**위임 프롬프트:**

```
다음 계획을 읽고 Step N을 실행하세요.

계획 디렉토리: {계획 디렉토리 절대 경로}
프로젝트 루트: {프로젝트 루트 절대 경로}

실행 절차:
1. plan.md를 읽고 ## 개요, ## 결정 사항, ## 고려사항, ## 추가 요청 사항을 파악
2. execution.md를 읽고 Step N의 참조 스킬·맥락을 파악
3. plan.md에서 Step N의 목표·작업 내용을 파악
4. 이전 Step에서 생성/수정된 파일이 있으면 해당 파일을 Read하여 현재 상태를 파악
5. Step의 `참조 스킬` 파일을 읽어 규칙 로드 ({프로젝트 루트}/.claude/skills/{스킬명}/SKILL.md)
6. 스킬 규칙에 따라 작업 내용을 순서대로 수행. 각 세부 작업 완료 시마다 plan.md의 체크박스를 [x]로 업데이트
7. 모든 작업 완료 후 execution.md의 ## 진행 상황 섹션의 해당 Step 체크박스를 [x]로 업데이트
```

**주의사항:**

- Agent 도구(`subagent_type: "general-purpose"`)로 서브에이전트 생성
- Step 간 의존성이 있으므로 반드시 순차 실행 (병렬 실행 금지)

## 프롬프트 참조

- **계획 검증**: [plan-validation-prompt.md](../prompts/plan-validation-prompt.md)
- **스킬 준수 검증**: 아래 "스킬 준수 검증 서브에이전트 프롬프트" 참조

## 검증

> 모든 구현 Step 완료 후, 오케스트레이터가 이 계획의 특성에 맞는 검증 항목을 판단하고
> 항목별 서브에이전트를 **병렬로** 실행하여 구현 결과를 검증한다.
> 검증 에이전트는 문제를 보고만 하고, 수정은 오케스트레이터가 판단한다.

### 필수 검증

- [ ] 타입체크 (`pnpm [앱-alias] tsc`)
- [ ] 린트 (`pnpm [앱-alias] lint`)

### 스킬 준수 검증

> 오케스트레이터가 구현 완료 후, 각 Step의 `참조 스킬`을 수집하여 고유 스킬별로 검증 에이전트를 병렬 생성한다.
> `없음 (CLAUDE.md 컨벤션 적용)` Step은 제외한다.

(오케스트레이터가 아래 형식으로 동적 생성)

- [ ] `스킬명` 준수 검증 → 대상 파일: `파일1`, `파일2`

**스킬 준수 검증 서브에이전트 프롬프트:**

```
당신은 코드 검증자입니다. 구현된 코드가 프로젝트 스킬 규칙을 준수하는지 검토하세요.

스킬 파일: {프로젝트 루트}/.claude/skills/{스킬명}/SKILL.md
검증 대상 파일: {대상 파일 절대 경로 목록}
계획 디렉토리: {계획 디렉토리 절대 경로} (plan.md 맥락 참조용)

## 검증 절차

1. 스킬 파일(SKILL.md)을 읽고, 스킬이 정의한 규칙을 파악한다
   - SKILL.md에서 참조하는 별도 파일(patterns.md 등)이 있으면 함께 읽는다
2. 검증 대상 파일을 각각 읽는다
3. 각 파일이 스킬 규칙을 준수하는지 항목별로 검토한다
4. plan.md의 해당 Step 맥락을 참고하여, 의도적인 예외인지 판단한다

## 검증 기준

- 스킬이 정의한 **파일 위치·네이밍 규칙**을 따르는가?
- 스킬이 정의한 **코드 패턴·구조 규칙**을 따르는가?
- 스킬이 정의한 **import 규칙**을 따르는가?
- 스킬에 금지된 패턴이 있다면, 해당 패턴을 사용하지 않았는가?

## 출력 형식

### 검증 결과: [통과 / 위반 발견]

**검증 스킬**: {스킬명}
**검증 대상**: {파일 수}개 파일

**위반 사항:** (위반 발견 시에만)

| 파일 | 줄 | 위반 규칙 | 설명 |
|------|-----|-----------|------|
| (파일 경로) | (줄 번호) | (스킬 내 규칙명) | (구체적 위반 내용) |

**참고:** (위반은 아니지만 개선 가능한 사항, 없으면 생략)
```

### 추가 검증

(오케스트레이터가 계획 특성에 따라 동적으로 결정하여 기록)

- [ ] (해당 시 추가)

## 진행 상황

> 각 Step별 체크박스를 기록한다. 재개 시 이 섹션을 파싱하여 진행 지점을 결정한다.

- [ ] Step 1: [단계 제목]
- [ ] Step 2: [단계 제목]
- [ ] 검증
````
